# Архитектура App_helper_1

## 1. Общая модель

Проект строится как единый `AI Agent Core` с отдельными платформенными адаптерами и отдельным персональным контекстом каждого пользователя.

```text
Android Adapter ─┐
iOS Adapter     ─┼──> AI Agent Core ──> Action Manager
MAX Adapter     ─┘          │
                            ├── Personal Memory
                            ├── User Preferences
                            ├── Interests
                            ├── Permissions
                            └── Conversation Context
```

## 2. Принцип персонализации

У каждого пользователя создаётся отдельный персональный контекст.

Он включает:

- профиль пользователя;
- контакты и связи между людьми;
- важные места;
- интересы;
- предпочтения по стилю общения;
- темп речи;
- историю разрешённых взаимодействий;
- правила автономности агента;
- долговременную память;
- краткосрочный контекст диалога.

Данные разных пользователей не смешиваются.

## 3. Типы памяти

### Профиль

Имя, язык, пользовательский режим, настройки голоса и интерфейса.

### Долговременные знания

Семья, важные контакты, интересы, часто используемые места, устойчивые предпочтения.

### Краткосрочный контекст

Недавний разговор, текущее действие, активный маршрут, незавершённый сценарий.

### Правила агента

Что агент может делать самостоятельно, что требует подтверждения, а что запрещено.

## 4. Action Manager

AI-модель не должна напрямую выполнять чувствительные действия.

Поток:

```text
Речь пользователя
      ↓
Распознавание намерения
      ↓
AI / NLU
      ↓
Action Manager
      ↓
Проверка разрешений
      ↓
Подтверждение при необходимости
      ↓
Платформенный API
```

Примеры чувствительных действий:

- звонок;
- отправка сообщения;
- запись контакта;
- передача геопозиции;
- изменение системных настроек;
- автоматический ответ от имени пользователя.

## 5. Платформенные адаптеры

### Android

Приоритетная платформа для MVP.

Планируемые интеграции:

- уведомления;
- Accessibility API;
- телефонные события;
- контакты;
- Text-to-Speech;
- Speech-to-Text;
- GPS;
- камера;
- системные intents.

### iOS

Использует отдельный адаптер. Общая бизнес-логика и AI-ядро остаются едиными, но доступ к функциям устройства ограничивается разрешёнными Apple API.

### MAX

MAX рассматривается как один из каналов коммуникации. Он не заменяет мобильное приложение.

## 7. Пользовательские режимы

### Accessibility Mode

Для слабовидящих и незрячих пользователей.

### Simple Mode

Для пожилых пользователей и людей, которым сложно пользоваться смартфоном.

Основные правила:

- более медленная речь;
- короткие предложения;
- один вопрос за раз;
- увеличенное время ожидания ответа;
- спокойное повторение вопроса;
- минимум вариантов одновременно.

### Voice Preferred Mode

Для пользователей без выраженных ограничений, предпочитающих голосовое управление.

Режимы могут сочетаться.

## 8. Международный режим

Первый приоритет — Испания.

Функции:

- русский ↔ испанский перевод;
- голосовой режим живого диалога;
- чтение испанских надписей камерой;
- GPS и локальные маршруты;
- сохранение домашней/гостиничной точки;
- помощь при потере ориентации.

## 9. Безопасность

Обязательные принципы:

- минимально необходимые разрешения;
- явное подтверждение чувствительных операций;
- возможность узнать, что агент помнит;
- возможность удалить конкретное знание;
- отдельное согласие на создание и использование персонального синтетического голоса;
- журнал значимых действий агента;
- отсутствие скрытых автономных действий.
