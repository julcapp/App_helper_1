# Точка остановки проекта — 28.08.2026

Статус: проект временно поставлен на паузу по решению пользователя.

Этот документ фиксирует последние принятые решения и точку, с которой следует продолжить работу.

## 1. Главный приоритет продукта

Главным модулем остаётся **Message Assistant** — голосовая работа с входящими сообщениями и уведомлениями.

Целевой цикл:

`новое сообщение → источник и отправитель → спросить «Прочитать?» → прочитать исходный текст → объяснить → сказать главное → определить явную просьбу → извлечь факты → подготовить ответ → прочитать ответ → подтверждение пользователя → разрешённая отправка`.

Исходный текст сообщения всегда отделяется от AI-интерпретации.

AI не получает права выполнять действия от имени пользователя.

## 2. Текущий технический статус Message Assistant

На Android уже реализованы и собраны:

- получение доступных Android-уведомлений;
- определение доступного приложения-источника и отправителя;
- голосовой вопрос «Прочитать?»;
- чтение доступного текста уведомления;
- состояние текущего сообщения после чтения;
- команды «Повтори», «Есть ли дата?», «Есть ли время?», «Есть ли телефон?», «Есть ли сумма?», «Есть ли ссылка?», «Закрой сообщение»;
- локальное фактическое извлечение данных из текста;
- команды «Объясни», «Скажи проще», «Что главное», «Что от меня хотят»;
- Android-контракт `MessageAnalysisProvider` для смыслового AI-анализа;
- серверный AI Gateway для обращения к OpenAI;
- защита от прямого хранения OpenAI API-ключа в Android APK.

Последняя связка Android + AI-клиент успешно прошла Android CI (`assembleDebug`).

Важно: настоящий удалённый AI-анализ заработает только после развёртывания AI Gateway на сервере и настройки его адреса в приложении.

## 3. AI Gateway

Принята архитектура:

`Android-приложение → собственный AI Gateway → OpenAI API`.

Запрещено:

- вшивать `OPENAI_API_KEY` в APK;
- хранить API-ключ в GitHub;
- передавать ключ в пользовательский интерфейс приложения.

Ключ хранится только на сервере как защищённая переменная окружения `OPENAI_API_KEY`.

AI Gateway возвращает структурированный анализ текущего сообщения, включая:

- краткое главное содержание;
- объяснение простыми словами;
- явную просьбу/требуемое действие, если оно действительно следует из текста;
- уровень неопределённости.

При неоднозначном сообщении помощник обязан сообщить об этом пользователю и не выдавать предположение за факт.

## 4. Сервер

Для AI Gateway принят существующий VPS пользователя у **Aeza** с **Ubuntu**.

Сервер подходит, поскольку AI-модель локально не запускается: VPS только принимает запрос Android-приложения, обращается к OpenAI API и возвращает результат.

При продолжении работы необходимо:

1. подключиться к Aeza VPS по SSH;
2. установить/проверить Python и необходимые зависимости;
3. развернуть `server/ai-gateway`;
4. установить `OPENAI_API_KEY` только на сервере;
5. оформить приложение как `systemd`-сервис;
6. поставить Nginx;
7. подключить HTTPS;
8. проверить AI Gateway тестовым запросом;
9. записать URL шлюза в Android-конфигурацию;
10. собрать новый APK и протестировать на реальном устройстве.

## 5. Отдельный домен проекта

Принято зарегистрировать **новый самостоятельный домен специально для проекта голосового AI-помощника**.

Не использовать домены других проектов пользователя.

Требования к названию:

- короткое;
- легко произносится голосом;
- легко запоминается;
- не привязано только к одной функции;
- пригодно для развития полноценного бренда помощника.

Предварительная структура после регистрации:

- `app.<домен>` — приложение / веб-интерфейс;
- `api.<домен>` — основной API;
- `ai.<домен>` — AI Gateway;
- `account.<домен>` — личный кабинет в будущем;
- `docs.<домен>` — документация при необходимости.

Первым обязательным поддоменом для текущего этапа будет `ai.<домен>` с DNS-записью на IP Aeza VPS.

Перед покупкой домена требуется отдельно подобрать и проверить доступность вариантов названия.

## 6. Второй основной пользовательский модуль — «Мои мысли»

Принят отдельный модуль **«Мои мысли / Голосовой блокнот»**.

Подробная спецификация находится в `docs/VOICE_NOTEBOOK.md`.

Назначение:

- голосовая запись мысли или идеи;
- сохранение исходного аудио;
- транскрипция голоса в текст;
- отдельное хранение исходной транскрипции;
- AI-очистка и структурирование только как производная версия;
- папки и темы;
- возврат к старым идеям;
- дополнение существующих идей новыми голосовыми фрагментами;
- история изменений;
- подготовка текста для передачи контрагентам;
- передача через системный Android Share и, позднее, прямые разрешённые адаптеры мессенджеров/e-mail;
- никакой отправки без подтверждения пользователя.

Этот модуль является вторым основным пользовательским модулем после Message Assistant и не должен задерживать завершение основного сценария сообщений.

## 7. Следующий этап после возобновления

Продолжать в следующем порядке:

### Шаг 1 — инфраструктура AI

- подобрать/зарегистрировать отдельный домен проекта;
- создать `ai.<домен>`;
- направить DNS на Aeza VPS;
- развернуть AI Gateway на Ubuntu;
- безопасно установить `OPENAI_API_KEY`;
- проверить запрос к OpenAI через Gateway.

### Шаг 2 — реальный AI-анализ сообщения

Проверить на настоящем Android-устройстве команды:

- «Объясни»;
- «Скажи проще»;
- «Что здесь главное?»;
- «Что от меня хотят?».

Проверить отсутствие домыслов и корректную обработку неоднозначности.

### Шаг 3 — подготовка голосового ответа

Реализовать:

`«Что можно ответить?» → AI готовит черновик → помощник читает его → пользователь может изменить голосом → помощник повторяет окончательный текст → пользователь подтверждает → только затем разрешённая отправка`.

### Шаг 4 — каналы отправки

Сначала использовать безопасные системные возможности Android, затем отдельно проверять и подключать официальные адаптеры MAX, Telegram, VK и e-mail в пределах их реальных API-возможностей.

### Шаг 5 — «Мои мысли»

После стабилизации Message Assistant перейти к реализации Voice Notebook по `docs/VOICE_NOTEBOOK.md`.

## 8. Правило возобновления проекта

При следующем продолжении не начинать проект заново и не пересматривать уже принятые решения без причины.

Стартовая точка: **домен → Aeza/Ubuntu → AI Gateway → реальный AI-анализ → голосовой черновик ответа → подтверждённая отправка**.
