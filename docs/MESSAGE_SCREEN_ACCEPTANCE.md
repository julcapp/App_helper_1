# Приёмка доступного экрана сообщения

Дата: 2026-10-31. Ветка: ux/discovery-accessibility-2026-10.
Статус: тест-план, не отчёт об успешных испытаниях.

## Основной сценарий
1. Получить одно тестовое уведомление с разрешённым содержимым.
2. Выбрать «Прочитать вслух». Проверить, что появляется блок «Работа с сообщением».
3. Нажать «Прочитать ещё раз»: услышать именно доступный исходный текст, а не AI-пересказ.
4. Нажать «Объяснить простыми словами»: проверить, что ответ явно представляет собой интерпретацию и не добавляет фактов.
5. Нажать «Что главное?»: проверить краткость и сохранение ключевого смысла.
6. Нажать «Закрыть сообщение»: вернуться к следующему сообщению, если оно есть.

## Ошибки и гонки
- Пока выполняется AI-анализ, закрыть сообщение: поздний ответ не должен озвучиваться.
- Пока выполняется анализ, переключиться на другое сообщение: ответ старого анализа не должен относиться к новому.
- Прервать речь кнопкой «Отмена» и проверить отсутствие выполнения поздней команды.
- Получить второе уведомление при чтении первого: первое сообщение должно оставаться активным.
- Отключить сеть: исходное сообщение должно остаться доступным, AI-ошибка не должна удалять сессию.
- При поступлении звонка: прервать голосовую активность без автоматического озвучивания приватного текста.

## Доступность
- TalkBack: проверить порядок фокуса, семантические заголовки и понятные названия всех действий.
- Масштаб шрифта 200%: ничего не обрезается, можно прокручивать без жестов высокой точности.
- Проверить действия без голосового ввода, с отключённым микрофоном.
- Проверить устройство с экраном шириной 320dp.
- Проверить гарнитуру и разговор через динамик, чтобы личный текст не звучал без разрешения.
- Два разных пользователя и разные настройки: память и содержание сообщений не должны смешиваться.

## Ограничения текущей реализации
- Отдельная кнопка «Ответить» и отправка не включены: нужен безопасный черновик и подтверждённый платформенный адаптер.
- Персистентная очередь после перезапуска и восстановление всех сессий остаются открытыми задачами.
- Требуются тесты на устройстве; успешный Gradle build не подтверждён.
- Проверка ID защищает от позднего ответа для другого сообщения, но после отмены внутри той же сессии остаётся необходимость токена запроса/отмены AI.
