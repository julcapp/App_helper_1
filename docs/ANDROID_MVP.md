# Android MVP — технический каркас

Статус: начат 26.08.2026.

## Зафиксированный стек

- Kotlin 2.3.21
- Android Gradle Plugin 9.3.0
- compileSdk 37
- targetSdk 37
- minSdk 26
- Jetpack Compose BOM 2026.08.00
- Material 3
- JDK 17

## Реализовано в текущем каркасе

1. Создан Android-модуль `app`.
2. Добавлен первый Compose-экран onboarding.
3. Пользователь может выбрать один или несколько режимов помощи:
   - слабовидящий пользователь;
   - простой режим телефона;
   - голосовое управление.
4. Добавлена доменная модель `UserProfile`:
   - режим помощи;
   - настройки речи;
   - разрешения агента;
   - интересы;
   - статус завершения onboarding.
5. Добавлен контракт `VoiceAssistant`.
6. Добавлена Android-реализация голосового слоя:
   - TextToSpeech;
   - SpeechRecognizer;
   - русский язык по умолчанию;
   - обработка результата распознавания и ошибок.
7. В манифесте подготовлены базовые разрешения для:
   - микрофона;
   - контактов;
   - геолокации.

## UX-принципы, уже отражённые в коде

- крупная типографика;
- крупные зоны нажатия;
- высокий контраст;
- понятные формулировки;
- semantic contentDescription для TalkBack;
- возможность сочетать несколько режимов помощи;
- голос рассматривается как основной интерфейс, а не как дополнительная кнопка.

## Что пока намеренно не подключено

Каркас не считается завершённым Android MVP. Следующие части должны быть добавлены последовательно:

1. Runtime Permission Flow для микрофона, контактов и геолокации.
2. Второй экран onboarding — настройка темпа речи и режима «один вопрос — одно действие».
3. Сохранение `UserProfile` в локальное хранилище.
4. Голосовой запуск первого сценария.
5. NotificationListenerService.
6. Контакты и определение имени звонящего.
7. CallScreeningService / телефонный слой в рамках разрешённых Android API.
8. GPS и безопасные точки.
9. Интеграция MAX как отдельный адаптер.
10. Agent Core и Action Manager.

## Важное правило

AI-модель не должна напрямую выполнять чувствительные действия. Действие проходит через Action Manager: распознанное намерение → проверка полномочий → при необходимости подтверждение пользователя → системный Android API.

## Следующий технический шаг

Собрать полноценный first-run flow:

`выбор режима → настройки речи → имя пользователя → интересы → доверенный контакт → разрешения → тест голоса → завершение onboarding`.
