# Android MVP — технический каркас

Статус: в работе с 26.08.2026.

## Зафиксированный стек

- Kotlin 2.3.21
- Android Gradle Plugin 9.3.0
- compileSdk 37
- targetSdk 37
- minSdk 26
- Jetpack Compose BOM 2026.08.00
- Material 3
- JDK 17

## Реализовано

1. Создан Android-модуль `app`.
2. Реализован многошаговый Compose onboarding.
3. Пользователь может выбрать один или несколько режимов помощи: слабовидящий, простой режим телефона, голосовое управление.
4. Реализованы настройки речи, имя пользователя, интересы и доверенный контакт.
5. Добавлен runtime-запрос разрешения микрофона и финальная голосовая проверка TextToSpeech.
6. `UserProfile` сохраняется локально через `UserProfileStore`.
7. Android-голосовой слой поддерживает TextToSpeech, SpeechRecognizer и изменение скорости речи.
8. В манифесте подготовлены разрешения микрофона, контактов и геолокации.
9. Реализован `NotificationListenerService` и зарегистрирован в AndroidManifest с системным `BIND_NOTIFICATION_LISTENER_SERVICE`.
10. Добавлена модель `NotificationEvent` и ограниченная очередь последних событий.
11. Для входящего уведомления извлекаются только реально опубликованные поля Android: приложение, title, text/bigText.
12. Собственные уведомления приложения отфильтровываются, чтобы исключить цикл самопрослушивания.
13. При новом событии помощник голосом сообщает: «Новое сообщение в <приложение> от <отправитель>. Прочитать?».
14. Реализован hands-free цикл: после фактического завершения TTS запускается SpeechRecognizer.
15. Добавлен `VoiceCommandRouter` для команд: «да/прочитай», «нет/позже», «повтори».
16. Команда «прочитай» озвучивает текст уведомления; «позже» завершает текущий диалог; «повтори» повторяет последний вопрос.
17. При неизвестной команде помощник уточняет допустимые варианты и снова слушает.
18. Callback завершения TTS переводится в главный Android-поток перед запуском SpeechRecognizer.
19. На главном экране остаются крупные резервные кнопки «Прочитать» и «Позже».
20. Добавлена кнопка перехода в системные настройки Android для выдачи доступа к уведомлениям.

## UX-принципы

- крупная типографика и крупные зоны нажатия;
- высокий контраст;
- простые формулировки;
- TalkBack-friendly семантика;
- один вопрос — одно действие для простого режима;
- голос является основным интерфейсом;
- кнопки сохраняются как резервный способ управления, но основной сценарий может выполняться без касания экрана.

## Важные ограничения текущего этапа

1. Очередь уведомлений пока живёт только в памяти процесса. Для журнала пропущенных событий нужна постоянная локальная база.
2. Голосовой цикл реализован для одного активного вопроса. Следующий общий Agent/Dialog Manager должен управлять конкурирующими событиями и очередностью диалогов.
3. Текст уведомления доступен только если его реально публикует исходное Android-приложение. Скрытый текст приложение-помощник получить из уведомления не может.
4. Код ещё не прошёл полноценную Gradle-сборку и тестирование на реальном Android-устройстве/эмуляторе.

## Что ещё не подключено

1. Постоянный журнал уведомлений и пропущенных событий.
2. Runtime Permission Flow для контактов и геолокации.
3. Contacts Provider и определение имени звонящего.
4. Телефонный слой / CallScreeningService в рамках разрешённых Android API.
5. GPS и безопасные точки.
6. Интеграция MAX как отдельный адаптер.
7. Agent Core, Intent Router и Action Manager.
8. Постоянная персональная память уровня серверного AI-профиля.

## Важное правило

AI-модель не выполняет чувствительные системные действия напрямую:

`намерение → Action Manager → проверка разрешений → подтверждение пользователя → Android API`.

## Следующий технический шаг

Перейти к Contacts Provider и телефонному сценарию:

`входящий звонок → получить номер в рамках доступного Android API → найти контакт → голосом назвать имя или номер → после разговора при неизвестном номере предложить сохранить контакт`.

Параллельно подготовить постоянный журнал событий, чтобы команда «Что я пропустил?» могла работать после перезапуска приложения.
