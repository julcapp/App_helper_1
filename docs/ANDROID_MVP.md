# Android MVP — технический каркас

Статус: в работе с 26.08.2026.

## Зафиксированный стек

- Kotlin 2.3.21
- Android Gradle Plugin 9.3.0
- compileSdk 37
- targetSdk 37
- minSdk 26
- Jetpack Compose BOM 2026.08.00
- Material 3
- JDK 17

## Реализовано

1. Создан Android-модуль `app`.
2. Реализован многошаговый Compose onboarding.
3. Пользователь может выбрать один или несколько режимов помощи:
   - слабовидящий пользователь;
   - простой режим телефона;
   - голосовое управление.
4. Реализована настройка речи:
   - более медленный темп;
   - больше времени на ответ;
   - короткие фразы и повтор важных вопросов заложены в профиль.
5. Реализован ввод имени пользователя.
6. Реализован выбор интересов для будущего режима собеседника.
7. Реализован ввод доверенного контакта.
8. Добавлен runtime-запрос разрешения микрофона.
9. Добавлена финальная голосовая проверка TextToSpeech.
10. `UserProfile` сохраняется локально через `UserProfileStore`.
11. После завершения onboarding приложение переходит на базовый главный экран.
12. Расширена доменная модель `UserProfile`:
   - режимы помощи;
   - настройки речи;
   - разрешения;
   - интересы;
   - доверенный контакт;
   - безопасные точки как модель данных;
   - основной язык `ru`;
   - язык поездок `es`;
   - статус завершения onboarding.
13. Добавлен контракт `VoiceAssistant`.
14. Android-реализация голосового слоя поддерживает:
   - TextToSpeech;
   - SpeechRecognizer;
   - русский язык;
   - изменение скорости синтеза речи;
   - обработку результата и ошибок.
15. В манифесте подготовлены базовые разрешения для микрофона, контактов и геолокации.

## UX-принципы

- крупная типографика;
- крупные зоны нажатия;
- высокий контраст;
- простые формулировки;
- semantic contentDescription для TalkBack;
- возможность сочетать несколько режимов помощи;
- один вопрос — одно действие для простого режима;
- голос является основным интерфейсом, а не дополнительной функцией.

## Что ещё не подключено

1. Runtime Permission Flow для контактов и геолокации.
2. Настоящий главный экран вместо временного `HomePlaceholder`.
3. NotificationListenerService и чтение входящих уведомлений.
4. Работа с Contacts Provider и определение имени звонящего.
5. Телефонный слой / CallScreeningService в рамках разрешённых Android API.
6. Журнал пропущенных событий.
7. GPS и безопасные точки.
8. Интеграция MAX как отдельный адаптер.
9. Agent Core, Intent Router и Action Manager.
10. Постоянная персональная память уровня серверного AI-профиля.

## Важное правило

AI-модель не выполняет чувствительные системные действия напрямую. Целевая схема:

`намерение → Action Manager → проверка разрешений → подтверждение пользователя при необходимости → Android API`.

## Следующий технический шаг

Перейти к первому полезному системному сценарию Android:

`входящее уведомление → определить приложение и отправителя → сохранить событие → голосом сообщить пользователю → спросить «прочитать?» → по подтверждению озвучить текст`.

Параллельно подготовить работу с контактами, чтобы следующим сценарием реализовать входящий звонок и голосовое произнесение имени абонента.
