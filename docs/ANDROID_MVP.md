# Android MVP — технический каркас

Статус: в работе с 26.08.2026.

## Зафиксированный стек

- Kotlin 2.3.21
- Android Gradle Plugin 9.3.0
- compileSdk 37
- targetSdk 37
- minSdk 26
- Jetpack Compose BOM 2026.08.00
- Material 3
- JDK 17
- Google Play services Location 21.4.0

## Реализовано

1. Создан Android-модуль `app`.
2. Реализован многошаговый Compose onboarding.
3. Пользователь может выбрать один или несколько режимов помощи: слабовидящий, простой режим телефона, голосовое управление.
4. Реализованы настройки речи, имя пользователя, интересы и доверенный контакт.
5. Добавлен runtime-запрос разрешения микрофона и финальная голосовая проверка TextToSpeech.
6. `UserProfile` сохраняется локально через `UserProfileStore`.
7. Android-голосовой слой поддерживает TextToSpeech, SpeechRecognizer и изменение скорости речи.
8. В манифесте подготовлены разрешения микрофона, чтения контактов и геолокации.
9. Реализован `NotificationListenerService` и зарегистрирован в AndroidManifest с системным `BIND_NOTIFICATION_LISTENER_SERVICE`.
10. Добавлена модель `NotificationEvent` и ограниченная очередь последних событий.
11. Для входящего уведомления извлекаются только реально опубликованные поля Android: приложение, title, text/bigText.
12. Собственные уведомления приложения отфильтровываются, чтобы исключить цикл самопрослушивания.
13. При новом событии помощник голосом сообщает: «Новое сообщение в <приложение> от <отправитель>. Прочитать?».
14. Реализован hands-free цикл: после фактического завершения TTS запускается SpeechRecognizer.
15. Добавлен `VoiceCommandRouter` для команд: «да/прочитай», «нет/позже», «повтори», «что я пропустил».
16. Команда «прочитай» озвучивает текст уведомления; «позже» завершает текущий диалог; «повтори» повторяет последний вопрос.
17. При неизвестной команде помощник уточняет допустимые варианты и снова слушает.
18. Callback завершения TTS переводится в главный Android-поток перед запуском SpeechRecognizer.
19. На главном экране остаются крупные резервные кнопки «Прочитать» и «Позже».
20. Добавлена кнопка перехода в системные настройки Android для выдачи доступа к уведомлениям.
21. Добавлен `ContactLookup` на базе `ContactsContract.PhoneLookup.CONTENT_FILTER_URI` для быстрого поиска имени контакта по номеру.
22. Добавлен runtime-запрос `READ_CONTACTS` на главном экране.
23. Добавлена модель `CallEvent` и локальная шина событий звонков.
24. Реализован `AppCallScreeningService` на базе Android `CallScreeningService`.
25. Сервис зарегистрирован с `android.permission.BIND_SCREENING_SERVICE`.
26. Пользователь может явно выдать приложению системную роль `RoleManager.ROLE_CALL_SCREENING` через кнопку «Включить определитель звонков».
27. При входящем вызове сервис получает доступный системе номер, при наличии разрешения ищет имя в контактах и публикует событие.
28. Помощник голосом произносит имя контакта либо номер/«неизвестный номер».
29. `CallScreeningService` не блокирует и не отклоняет вызовы: текущая версия используется только для caller ID и всегда разрешает входящий звонок.
30. Добавлен постоянный `EventJournal` на локальном хранилище приложения.
31. Журнал сохраняет уведомления и события звонков и переживает перезапуск приложения.
32. Журнал ограничен последними 100 событиями, поддерживает состояние «просмотрено/не просмотрено».
33. Добавлена команда «Что я пропустил?» и варианты «что пропустил», «что было», «пропущенные события».
34. Помощник формирует голосовую сводку: количество звонков и уведомлений плюс детали последних пяти событий.
35. После озвучивания события помечаются просмотренными.
36. На главном экране добавлены крупные действия «Слушаю» и «Что я пропустил?».
37. Для общей голосовой команды микрофон запускается только после завершения фразы TTS «Слушаю».
38. Добавлен `UnknownCallerStore`: последний неизвестный входящий номер сохраняется между запусками приложения.
39. Принято архитектурное решение НЕ становиться полноценным системным dialer только ради события завершения звонка.
40. Для MVP неизвестный номер предлагается сохранить при следующем активном взаимодействии пользователя с помощником.
41. При следующем действии «Слушаю» помощник спрашивает: «Последний неизвестный номер ... Сохранить в контакты?».
42. После ответа «да» помощник спрашивает имя контакта голосом.
43. После распознавания имени открывается системная форма Android создания контакта с подставленными номером и именем.
44. Перед фактическим сохранением пользователь видит системную форму и может проверить/изменить данные.
45. Для создания контакта используется `Intent.ACTION_INSERT`; прямое разрешение `WRITE_CONTACTS` не требуется.
46. На главном экране добавлена резервная кнопка «Сохранить в контакты» для последнего неизвестного номера.
47. Добавлен `LocationAssistant` на базе `FusedLocationProviderClient.getCurrentLocation()`.
48. Реализован runtime-запрос `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`.
49. Добавлена команда «Где я?» и несколько естественных вариантов формулировки.
50. Помощник получает свежую доступную позицию и озвучивает координаты и фактическую точность, если Android её предоставил.
51. Добавлен `SafePlaceStore` и безопасная точка «Дом» с координатами, сохраняемая между запусками приложения.
52. Добавлены команды «Запомни это место как дом» / «Сохрани дом».
53. Добавлена команда «Отведи меня домой» / «Веди домой».
54. Для маршрута используется внешний картографический сервис через универсальный Google Maps directions URL; собственный неподтверждённый маршрутизатор в MVP не создаётся.
55. На главном экране добавлены резервные действия «Где я?», «Запомнить это место как дом» и «Отведи меня домой».

## UX-принципы

- крупная типографика и крупные зоны нажатия;
- высокий контраст;
- простые формулировки;
- TalkBack-friendly семантика;
- один вопрос — одно действие для простого режима;
- голос является основным интерфейсом;
- кнопки сохраняются как резервный способ управления;
- системные роли и чувствительные разрешения запрашиваются явно;
- для записи нового контакта используется системная форма;
- геолокация запрашивается только по действию пользователя, постоянное фоновое отслеживание в текущем MVP не используется.

## Важные ограничения текущего этапа

1. Постоянный журнал реализован через компактное локальное хранилище. При росте объёма следует перейти на Room.
2. Голосовой цикл рассчитан на один активный диалог. Общий Agent/Dialog Manager должен управлять конкурирующими событиями.
3. Текст уведомления доступен только если его реально публикует исходное Android-приложение.
4. `CallScreeningService` работает только после явного выбора приложения пользователем в роли CALL_SCREENING.
5. `CallScreeningService` не предоставляет надёжное событие «разговор завершён».
6. Переход на `ROLE_DIALER` отложен как избыточный для текущего MVP.
7. Постоянно слушающий микрофон намеренно не используется.
8. Команда «Где я?» сейчас сообщает реальные координаты и доступную точность. Человеко-читаемый адрес ещё не реализован, поэтому приложение не должно придумывать улицу или объект рядом.
9. «Отведи меня домой» сейчас передаёт сохранённую точку внешнему картографическому приложению. Встроенной пошаговой навигации внутри App_helper пока нет.
10. Код ещё не прошёл полноценную Gradle-сборку и тестирование на реальном Android-устройстве/эмуляторе.

## Что ещё не подключено

1. Reverse geocoding для безопасного голосового ответа «Вы находитесь по адресу ...».
2. Несколько безопасных точек: дом, гостиница, временное место проживания.
3. Пеший режим и контролируемая передача маршрута в карты.
4. Сценарий «Я заблудился» с предложением маршрута и доверенного контакта.
5. Интеграция MAX как отдельный адаптер.
6. Agent Core, Intent Router и Action Manager.
7. Постоянная персональная память уровня серверного AI-профиля.
8. Перенос EventJournal на Room при необходимости расширенного журнала и аналитики.
9. Полноценный default-dialer режим — только если позже будет отдельное продуктовое решение заменить системное приложение «Телефон».

## Важное правило

AI-модель не выполняет чувствительные системные действия напрямую:

`намерение → Action Manager → проверка разрешений → подтверждение пользователя → Android API`.

## Следующий технический шаг

1. Добавить reverse geocoding и понятный голосовой ответ на «Где я?», не скрывая возможную неточность геокодера.
2. Расширить безопасные точки: «Дом», «Гостиница», «Текущее место проживания».
3. Реализовать сценарий «Я заблудился»: определить позицию → сообщить её → предложить маршрут к безопасной точке → предложить связаться с доверенным контактом.
4. После этого перейти к режиму поездки и русско-испанскому переводчику.
